# Free public demo (Render + Neon)

A public Mentora demo for ₹0: one Render free web service (FastAPI serving the built React
app at `/app`) and a Neon free PostgreSQL database (pgvector). No domain, no card, no API key.

> The demo runs on **synthetic course data and simulated history**. Nothing in it has been
> validated with real learners. Do not put real student data into the public demo.

## What runs where

| Part | Where | Free-tier terms (checked 2026-10-19) |
|---|---|---|
| API + web app | Render free web service, Docker, `render.yaml` | 512 MB RAM, 0.1 vCPU, 750 instance-hours/month, spins down after 15 min idle (~1 min cold start), ephemeral disk, no card needed |
| Database | Neon Free | 1 GB storage/project, 100 CU-hours/month, scales to zero after 5 min (sub-second wake), no card, does not expire; pgvector included |

Why not others: Render's own free Postgres is deleted 30 days after creation; Hugging Face
Docker Spaces now need a paid plan; Railway is a trial credit; Fly.io has no free tier for
new accounts.

### Demo configuration (in `render.yaml`)

| Setting | Value | Why |
|---|---|---|
| `MENTORA_LLM__BACKEND` | `offline` | Template replies, no API key. The UI shows a "Demo mode" notice. |
| `MENTORA_RAG__EMBEDDER` / `RERANKER` / `GROUNDING_JUDGE` | `hashing` / `lexical` / `lexical` | No model downloads; torch is never imported, so the API fits in 512 MB. **The DB must be seeded with the same embedder.** |
| `MENTORA_RAG__ANSWER_MODE` | `course_only` | Offline templates can only answer from the notes; `open` needs a real model. |
| `MENTORA_DEV_LOGIN` | `true` | No Moodle: sign in from the login page. |
| `MENTORA_DEV_TEACHER_CODE` | secret | Without it, anyone could sign in as a teacher. |
| `MENTORA_COOKIE_HTTPS_ONLY` | `true` | Render serves HTTPS. |
| `MENTORA_SESSION_SECRET`, `MENTORA_PSEUDONYM_SALT` | generated by Render | Keep the salt fixed once learners exist. |
| `MENTORA_DATABASE_URL` | secret | Neon connection string (below). |

## First deployment

### 1. Neon database

1. Sign up at <https://neon.tech> (GitHub sign-in, no card). Create a project, e.g. `mentora`,
   region **AWS Asia Pacific (Singapore)** to sit next to the Render service.
2. *Connect* → copy the connection string with **Connection pooling off** (the direct
   host, without `-pooler`). It looks like
   `postgresql://neondb_owner:<password>@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
3. Change the scheme to `postgresql+psycopg://` — that is `MENTORA_DATABASE_URL`.

### 2. Migrate and seed (once, from your computer)

Done locally so the 0.1 vCPU instance never runs the simulator or the offline pipeline.
PowerShell, from the repo root with the venv active:

```powershell
$env:MENTORA_DATABASE_URL = "postgresql+psycopg://neondb_owner:<password>@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require"
$env:MENTORA_RAG__EMBEDDER = "hashing"      # must match the deployed setting
$env:MENTORA_LLM__BACKEND = "offline"
# Optional, ONLY on the new empty database: migration + pgvector round-trip test.
# It runs `alembic downgrade base` (drops every table) and leaves test rows behind.
pytest -m postgres -p no:cacheprovider
alembic downgrade base                       # clean up the test rows (empty DB only!)
alembic upgrade head                         # schema v1 + CREATE EXTENSION vector
python scripts/seed_demo.py --with-history   # ONCE: --with-history adds 60 more simulated sessions per run
Remove-Item Env:MENTORA_DATABASE_URL, Env:MENTORA_RAG__EMBEDDER, Env:MENTORA_LLM__BACKEND
```

Never run `pytest -m postgres` or `alembic downgrade` against the database once the demo is
live. Re-running `seed_demo.py` without `--with-history` is safe (course, items, passages and the
rule policy are upserted).

### 3. Render service

1. Sign up at <https://render.com> with GitHub (Hobby workspace, no card).
2. *New* → *Blueprint* → pick this repository. Render reads `render.yaml`.
3. When asked, enter `MENTORA_DATABASE_URL` (step 1) and `MENTORA_DEV_TEACHER_CODE`
   (any long random string; share it only with demo teachers).
4. *Apply*. The first Docker build takes about 10 minutes. The container runs
   `alembic upgrade head` (a no-op after step 2) and starts Uvicorn on Render's `$PORT`.
5. Open `https://<service>.onrender.com/health`, then `/app/`.

### 4. Verify the live site

```bash
python scripts/smoke_deploy.py https://<service>.onrender.com --teacher-code <code>
```

It checks health, the web app and its assets, role separation, retrieval, a tutor session,
a quiz answer with confidence, a distress escalation answered by the teacher, and the
teacher console. It writes one demo learner and one escalation; that is expected.

## Updating

Push to `main`: Render rebuilds and redeploys automatically (`autoDeploy: true`). A new
Alembic migration runs on container start; with one instance there is never a competing
migration. Schema-changing deploys: back up first (Neon → *Branches* → create a branch is
an instant copy).

## Limits and risks

- **Cold starts**: after 15 idle minutes the service sleeps; the next visitor waits about a
  minute, plus a moment for Neon to wake.
- **Ephemeral disk**: anything written under the container (`models/`, trained policy
  files, `llm_cache/`) is lost on every restart or redeploy. Learner data, sessions,
  escalations, memory and uploaded course material are in Neon and survive.
- **Approving a learned policy** stores its model file on that ephemeral disk. After the
  next restart the file is gone and the tutor cannot load its policy. In the demo, approve
  only the rule policy, or retire the learned one (see below). Policy training in the
  console imports PyTorch and may run out of memory or take very long on 0.1 vCPU; run
  `python scripts/train_policy.py` locally against Neon instead.
- **Offline replies** are templates that quote course passages. They are not an LLM, the
  model-free retrieval is crude, and off-topic questions are not always recognised.
- `/api/rag/search` and `/docs` are public (they show only the synthetic course notes and
  the API schema).
- Neon Free: 1 GB storage and 100 CU-hours/month. A demo uses a small part; if exceeded,
  Neon suspends compute until next month (data is kept). Render: if free bandwidth or build
  minutes run out, the service is suspended for the month; nothing is charged without a
  card on file.
- Anyone with the URL can create demo learner accounts.

### Recovering from a lost policy file

```sql
-- in the Neon SQL editor: make the rule policy active again
UPDATE policies SET status = 'retired' WHERE status = 'active' AND type <> 'rule';
UPDATE policies SET status = 'active' WHERE version = 'rule-v1';
```

Then restart the service (Render → *Manual Deploy* → *Restart*).

## Optional: real LLM replies

**Claude (paid)**: set `ANTHROPIC_API_KEY` as a Render secret and
`MENTORA_LLM__BACKEND=hosted`, `MENTORA_RAG__ANSWER_MODE=open`. This leaves the ₹0 plan.

**Ollama on your own computer (free)**: the Render instance is too small to run a model,
so the deployed app calls your computer through a tunnel. Tutor replies only work while
your computer, Ollama, the gateway and the tunnel are all running; otherwise tutor turns
fail after the timeout (switch back to `offline` when you stop).

1. Pick a long random token. Start the gateway (never tunnel Ollama's port 11434 itself:
   its API can pull and delete models):
   `python scripts/ollama_gateway.py --token <token>` (listens on 127.0.0.1:11435).
2. In a second terminal, start a tunnel to the gateway, e.g. a free Cloudflare quick
   tunnel (no account): `cloudflared tunnel --url http://127.0.0.1:11435`. It prints an
   `https://<random>.trycloudflare.com` URL, which changes on every restart.
3. On Render set: `MENTORA_LLM__BACKEND=local`, `MENTORA_LLM__LOCAL_MODEL=llama3.2:3b`,
   `MENTORA_LOCAL_LLM_BASE_URL=https://<random>.trycloudflare.com/v1`,
   `MENTORA_LOCAL_LLM_API_KEY=<token>`, `MENTORA_LLM__TIMEOUT_S=180`,
   `MENTORA_RAG__ANSWER_MODE=open`, `MENTORA_RAG__ANSWER_REGENERATIONS=0`.
   Teacher console → System status shows whether the model is reachable.
4. To stop: set `MENTORA_LLM__BACKEND=offline` and `MENTORA_RAG__ANSWER_MODE=course_only`.
